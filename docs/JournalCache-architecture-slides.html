JournalCache for XRootD

Dr. Andreas-Joachim Peters — CERN IT-SD-PSS

XRootD Workshop Lyon 2026

XRootD

A client read cache, distinct from XCache

JournalCache records only the byte ranges an application reads, in an append-only per-file journal. There is no block size and no read amplification beyond the request.

Where

Client or proxy

An XrdCl file plugin for xrdcp, ROOT, or any XrdCl application. The same plugin can run under PSS or XrdHttp. xjcd installs a forwarding proxy.

What

Exact ranges

A hit requires the full request in the journal. A miss is fetched from the origin and appended. A write resets that file’s journal.

Scope

Not XCache

XCache (XrdPfc) is a shared, server-side block cache with prefetch. JournalCache is a client journal. The two are complementary.

Deployments

One plugin, two deployments

The file plugin is the cache. The HTTP extension and xjcd are optional: they expose the same journal as a forwarding proxy for browsers and HTTP clients.

Read path

A hit requires the full request

Partial coverage is a miss. The origin is read and the bytes are appended. There is no block size and no prefetch.

PgRead always goes to the origin (page checksums are not stored). Successful pages are still journaled for later Read. Write and Truncate reset that file’s journal.

Further processes, same fileRead from the origin (no shared writer)

Recursive, chunked, and ZIP listings are never cached. Rm, MkDir, and Mv invalidate listing and stat files.

On disk

Append-only fragments, not blocks

Layout

Default: <cache>/<host>:<port>/<path>/journal

  • flat = true — SHA256 directory per file
  • basepath = /store/ — omit the host; start at the federation prefix
  • Listings: .journalcache_list*
  • Stat: .journalcache_stat
  • Runtime state: $journal/.xjc/ (never evicted)

Journal file

Little-endian header, then fragments:

  • jheader_t — magic, mtime, filesize, version
  • header_t { offset, size } + data
  • v2: uint32 crc32c trailer per fragment
  • HTTP freshness in xattrs (etag, cache-control, …)
  • Symlink journals are refused (O_NOFOLLOW)
HTTP

Freshness is stored with the journal

CGI and the HTTP extension pass origin validators into XrdCl. A matching If-None-Match or If-Modified-Since can return 304 before the file is opened.

Cache-Control

  • no-store — do not journal
  • no-cache — Stat this session before serving
  • private — do not write the shared journal
  • max-age / s-maxage / Expires — expire from cached-at

HTTP ext (libXrdClJournalCacheHttpExt)

  • Maps request headers to CGI
  • Optional HEAD to http_origin
  • 304 when a validator still matches
  • Emits stored ETag / Last-Modified on continue
  • Enforces allow_origin even in bypass

Requires BUILD_HTTP=ON. Outbound HEAD does not follow redirects. http.header2cgi maps If-None-Match and If-Modified-Since.

Forwarding

The proxy stays closed until an origin is allowed

xjcd init writes configuration only. An empty allow_origin denies every chained URL (/https://…, /root://…, including N-hop unwrap).

Enable pss.permit in the generated xrootd.cf. Invalid regex is rejected by xjc allow-origin add.

Tools

Three tools, one cache tree

Policy

xjc

  • bypass, multi-origin, allowlist
  • external redirects
  • cleaner watermarks
  • Reloads policy.conf on change
Bootstrap

xjcd

  • init — state, units, TLS ports
  • render / validate / show
  • No xjcd run; systemd starts xrootd
  • --install-systemd installs the units
Evict

xjccleand

  • mtime eviction, skip .xjc/
  • Disabled until xjc cleaner enable on
  • Do not run together with in-plugin size=
  • Removes journal, list, and stat files only

XRD_LOGLEVEL=Info logs attach paths and hit rates. On exit (and with stats=N) the process reports hit rate, unique files, and the fraction of each dataset read.

XCache

XCache is the XRootD site cache

XCache is XrdPfc (Proxy File Cache) in front of PSS. It is a shared server: files are stored in fixed-size blocks (default 256 KiB) and neighbouring blocks can be prefetched.

XCache is the appropriate choice for a shared disk cache in front of a remote namespace. It is not a per-process client plugin.

Choice

Recommended use

JournalCache
  • A laptop or worker that rereads the same sparse ranges
  • ROOT or analysis that touches only selected branches or events
  • A compact HTTP forwarder for /https://origin/path
  • Workloads that must not fetch a whole file or a 256 KiB block
  • A closed origin allowlist and a hot-reloadable policy (xjc)
XCache
  • A site or campus cache in front of a federation
  • Many jobs reading the same files from one node
  • Sequential or wide reads, where prefetch is useful
  • An existing PSS deployment that needs a shared disk pool
  • Production purge, gstream monitoring, and multi-reader files

The two can run together. A site may operate XCache, while a client or xjcd instance still journals the ranges that client read.

Quick start

Client setup, then a closed proxy

Laptop

mkdir -p /var/tmp/journalcache/

export XRD_PLUGIN=libXrdClJournalCachePlugin-5.so

export XRD_JOURNALCACHE_CACHE=/var/tmp/journalcache/

xrdcp root://host:1094//store/file.root /tmp/out

xjcd proxy

xjcd init --journal /var/tmp/journalcache \

  --xroot-port 1094 --https-port 8443 \

  --tls-cert … --tls-key … --install-systemd

xjc allow-origin add '^https://.*\.example\.org/'

xjc cleaner enable on

Alternatively, /etc/xrootd/client.plugins.d/journalcache.conf with url=*, lib=…, and cache=…/. See src/XrdApps/XrdClJournalCachePlugin/README.md.
