JournalCache

XRootD client read cache. Only the byte ranges you actually read are stored, as an append-only per-file journal. Use it in a desktop client or as a forwarding proxy via xjcd.

App / browser→ XrdHttp ext (304, CGI)→ File plugin→ journal hit or origin, then journal

Tip. Run with XRD_LOGLEVEL=Info to see attach paths and hit rates.

Quick start

Client Laptop / batch job. Set the plugin and a cache directory, then use xrdcp or ROOT as usual.
Forwarding proxy xjcd init --install-systemd writes configs under $journal/.xjc/ and enables systemd. Add allow_origin with xjc.

Client on a laptop

mkdir -p /var/tmp/journalcache/
export XRD_PLUGIN=libXrdClJournalCachePlugin-5.so
export XRD_JOURNALCACHE_CACHE=/var/tmp/journalcache/
xrdcp root://host:1094//store/file.root /tmp/file.root

Or a numbered plugin:

export XRD_PLUGIN_1="lib=libXrdClJournalCachePlugin-5.so,enable=true,url=*,cache=/var/tmp/journalcache/"

Forwarding cache proxy (xjcd)

TLS cert and key are required. Initial policy is open (no allow_origin) until you add rules.

xjcd init --journal /var/tmp/journalcache \
  --xroot-port 1094 --https-port 8443 \
  --tls-cert /etc/xrootd/tls.crt --tls-key /etc/xrootd/tls.key \
  --install-systemd

xjc --journal /var/tmp/journalcache allow-origin add '^https://.*\.example\.org/'
xjc --journal /var/tmp/journalcache cleaner enable on
xjc --journal /var/tmp/journalcache cleaner set high 10737418240

Clients GET https://proxy/https://cdn.example.org/store/file.dat.

What gets cached

I/OBehaviour
Read / ReadVServed from the journal when the entire request is present; otherwise origin, then append.
PgReadAlways origin (page checksums are not stored). Pages are still written for later Read.
Write / Truncate / PgWritePassed through; that file’s journal is reset.
DirList / StatOptional filesystem plugin (system = true).

A journal is keyed by on-disk path, not URL. The first process takes an exclusive POSIX lock; later processes fall back to the origin. .. in paths is collapsed; layouts that would leave the cache root become a SHA256 directory under that root.

On-disk layout

Default (hierarchical):

<cache>/<host>:<port>/<remote-path>/journal
<cache>/<host>:<port>/<dir>/.journalcache_list
<cache>/<host>:<port>/<path>/.journalcache_stat

flat = true uses <cache>/<sha256(url+path)>/journal. basepath = /store/ drops the host prefix (federations; use async = 1, treat as WORM).

PathRoleEdit with
$journal/.xjc/state.confPorts, TLS, lib dirxjcd render
$journal/.xjc/policy.confbypass, allow_origin, redirectsxjc
$journal/.xjc/cleaner.confwatermarksxjc cleaner
$journal/.xjc/etc/xrootd.cf, HTTP ext, plugins, unitsxjcd render

The cleaner never deletes .xjc/. Eviction only removes journal, .journalcache_list*, and .journalcache_stat.

Journal format

jheader_t { magic=0xcafecafecafecafe, mtime, mtime_nsec, filesize,
            placeholder1=version (1=legacy, 2=crc32c), … }
header_t  { offset, size } + data[size] [ + uint32 crc32c if v2 ]

crc = true writes v2. Legacy journals stay readable. Bad fragments are skipped. HTTP headers live in user.journalcache.* xattrs.

Configuration

url = *
lib = /usr/lib64/libXrdClJournalCachePlugin-5.so
enable = true
cache = /var/tmp/journalcache/

The cache directory must exist; end the path with /.

HTTP freshness

CGIRole
xrd.journalcache.cache-control / expiresOrigin freshness
etag / last-modifiedGetters; also filled from Stat
if-none-match / if-modified-sinceValidators
async=1 / bypass=1 / clean=1Per-open toggles

no-store skips the journal. no-cache requires Stat this session. private is not stored on shared disk. max-age / s-maxage / Expires mark stale entries.

Build the HTTP ext with BUILD_HTTP=ON. Wire it:

http.header2cgi If-None-Match xrd.journalcache.if-none-match
http.header2cgi If-Modified-Since xrd.journalcache.if-modified-since
http.exthandler journalcache libXrdClJournalCacheHttpExt-5.so \
  /etc/xrootd/journalcache-http.ext.conf

Metadata order: client validators → file xattrs → optional HEAD to http_origin. Fresh validator match → 304. policy.bypass skips 304/CGI but still checks the allowlist. HEAD does not follow redirects.

Forwarding, allowlist, redirects

GET /https://cdn.example.org/store/file.dat
GET /root://origin.cern.ch:1094//store/file.dat
root://proxy//root://relay//root://origin.cern.ch:1094//store/file.dat

Allowlist matches the fully unwrapped URL. URL-shaped patterns are regex-searched; bare hosts must match the hostname exactly.

Open by default. Empty allow_origin (after xjcd init) allows every origin. Add rules with xjc and pss.permit in xrootd.cf.

External redirect (no journal): HTTP 302 or XrdCl errRedirect.

external_redirect = /live/ https://stream.example.org/live/
external_redirect = /live/|https://stream.example.org/live/,/raw/|root://data//raw/

Tools

xjc — policy and cleaner

xjc --journal /var/tmp/journalcache show
xjc bypass off
xjc allow-origin add '^https://.*\.example\.org/'
xjc redirect add /live/ https://stream.example.org/live/
xjc cleaner enable on
xjc cleaner set high 10737418240

xjcd — systemd proxy bootstrap

Commands: init, render, show, validate. No xjcd run — systemd starts xrootd. init writes open policy and a disabled cleaner.

xjcd init --journal /var/tmp/journalcache \
  --xroot-port 1094 --https-port 8443 \
  --tls-cert /path/tls.crt --tls-key /path/tls.key \
  --install-systemd
xjcd render --journal /var/tmp/journalcache
sudo systemctl restart xjcd.service xjccleand.service

xjccleand

Reads $journal/.xjc/cleaner.conf (hot-reload). Unit is enabled on install; cleaning stays off until xjc cleaner enable on.

enabled = 0
journal = /var/tmp/journalcache
high_watermark = 10737418240
low_watermark = 0
interval = 60
config_poll = 2

Do not run plugin size= and xjccleand on the same tree.

In-process cleaner

size = 10000000000 (or XRD_JOURNALCACHE_SIZE) starts a thread. High watermark = size, low = 90%, interval = 60 s. Same eviction rules as xjccleand. Off if size < 1 GiB.

Statistics and tests

Exit summary (and stats = N) prints hit rate, bytes, IOPS, unique files, open time, dataset fraction, and an ASCII rate plot. JSON: journalcache.<XRD_APPNAME|none>.<pid>.json.

Unit tests: tests/XrdCl/XrdClJournalCache.cc in xrdcl-unit-tests (journal, CRC, list/stat, headers, forwarding, allowlist, policy, xjcd). No live HTTP/XRootD suite in that binary.

./build/bin/xrdcl-unit-tests --gtest_filter='Journal*:ListCache*:CacheHeaders*:Forwarding*:Origin*:Policy*:Xjcd*:Cleaner*:CachePath*'

Manual proxy (no xjcd)

pss.origin xrootd.cern.ch
all.export /xrootd/
ofs.osslib libXrdPss.so

Forwarding: pss.origin =root,http,https, pss.permit, HTTP ext forwarding = 1. See http/journalcache-forwarding.cf.

Limitations

  • Exclusive flock — a second process on the same journal does not read it.
  • Attach scans every fragment (no compacted index).
  • async / federation basepath: no remote Stat on attach.
  • Empty allow_origin is an open forwarding proxy.
  • Not implemented: dynamic read-ahead; automatic connection demux.
